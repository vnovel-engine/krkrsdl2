# overrides.txt — data-driven plugin/resource overrides for the KiriKiri engine.
#
# Each line:  <fileName> <fileHash> <replacementFile> <needDecryption>
#   fileName         plugin/storage base name to match, or `-`
#   fileHash         XP3 per-file hash to match (hex), or `-`
#   replacementFile  `-` keep the file as the game shipped it (for a plugin: the
#                        engine answers the link itself), else one of:
#                          * `@builtin:<name>` — a shim compiled into the engine
#                            (src/shims/, reached through the registry in
#                            BuiltinShims.h). Preferred: nothing to install,
#                            no architecture to match.
#                          * a path relative to this directory, loaded by
#                            dlopen. It MUST match the target architecture — an
#                            x86-64 ELF can never load on an aarch64 device.
#   needDecryption   1 = apply the archive decryption to this file, else 0
#
# `#` starts a comment. Case-insensitive on the file name.
#
# Matching: a record matches only when every criterion it specifies is
# satisfied by the query — an unspecified field (`-`) is a wildcard, but a
# *specified* field that the query cannot supply does NOT match. So a record
# with name+hash needs both; hash-only matches by hash alone; name-only by
# name alone. Two games can therefore share a trivial file (a blank storage, a
# one-line config whose hash collides) and still be overridden differently:
#     player.conf  0x1a2b3c4d  A/player.conf  0   # game A -> hiro
#     player.conf  0x9e8d7c6b  B/player.conf  0   # game B -> masa
#
# A plugin whose Windows PE we cannot load but whose link must succeed.
# The behaviour, when any, is provided by the engine or the game's own scripts.
